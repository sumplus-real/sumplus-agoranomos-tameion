# Private business review and audit preparation

The importer verifies source hashes and references. A `confirmationRef` alone does not authenticate a business reviewer. `business_confirmed` now requires an Ed25519-signed review from an owner-provisioned reviewer registry, scoped to the case counterparty. The signature binds all bundle content except status, review, and confirmationRef. Review fields bind the outcome, original review timestamp, source reference, reason and measured human time. Keep bundles, trust registries and reviewer private keys outside git. Do not invent measured human time.

A real reviewer creates a signed review using `reviewPayload` and their own private key. Provision `TrustedReviewers` through the owner, outside agent control. The local workflow imports an unconfirmed bundle, verifies its source files and signed review, preserves the original, creates a new reviewed bundle and appends `human-reviews.jsonl`. Reusing the same signed review is refused. Rejections remain unconfirmed; confirmation is not payment permission. The business-facing signer `signBusinessCase` verifies the bundle and trusted review before applying rules v2. Raw `signCase` is an internal mechanism primitive; do not expose it directly to untrusted callers.

`npm run review:evidence -- bundle.json signed-review.json owner-trusted-reviewers.json reviewed.json` writes a new file beside the bundle. `npm run import:evidence -- reviewed.json owner-trusted-reviewers.json` checks it again. `npm run checkpoint:log -- human-reviews.jsonl business-review checkpoint.json` creates a hash commitment. Keep the checkpoint independently and use `verifyCheckpoint` against it. A consistently rewritten chain fails against the old retained checkpoint. This prepares external anchoring; no external publication, timestamp authority or chain anchoring has occurred. The review CLI uses an atomic writer lock and a durable review journal. A diagnostic interruption after output creation recovers on retry without double-counting, and changed output/journal content is refused. A SIGKILL or power loss can leave the writer lock; an owner must verify no writer is active before removing that stale lock. A partially written journal or log fails closed and needs owner-reviewed recovery.

`npm run agent:isolated -- command args...` applies a macOS sandbox denying the configured verifier/owner key paths and reviewer-key directory, including their resolved paths. It removes verifier/owner private-key environment variables. Positive-control tests prove the fixture is readable outside the sandbox and denied inside while public evidence remains readable. This is local defense, not separate OS users, remote custody, hardware isolation, or protection against copies/hard links of keys already held by the same user. Provision independent identities before relying on it in deployment.

`npm run test:local-v2` starts a disposable loopback-only EVM with Arc's chain ID and randomly generated temporary accounts. It runs v2 signing, payment, escalation, approval, rejection and refused controls against the current local contract. Test units are local mock balances, not Arc testnet funds or business adoption. No existing Arbitrum deployment or submission is modified. The deployed historical Arc contract remains unchanged and lacks the newly added approval safeguards; v2 production activation needs an owner-reviewed deployment/migration plan. `scripts/live-e2e.ts` defaults to disabled and refuses a mismatched deployed rule before setup.

No real business review or event-period usage is created by these fixture tests.
